MENTOVA UI CONVENTIONS

This file records standing rules for the web pages the Mentova server serves, so that future pages follow them.


WARM COLOUR PALETTE RULE

Every page the server serves uses one warm palette: crimson, red, gold, yellow, limoncello, light yellow, and dark red. Backgrounds are dark red; text is light yellow or gold; accents are crimson, yellow, and limoncello. There are no cool colours (no blue, no green) in the page chrome.

The reference values are:

• Dark red (page background): #2b0a0a

• Dark red (header, deep panels): #7b1113

• Panel/card background: #3a1212

• Crimson (headings, primary buttons): #dc143c and #b01030

• Red (warnings): #ff6b5a

• Gold (borders, accents, links): #d4af37 and #c9a227

• Yellow (highlights, active state): #ffd83b

• Limoncello (bright notices): #eef23a

• Light yellow (main text): #fdf3c7

How it is applied:

• The chat pages (index, mentor, terms) get the palette from CSS variables in assets/chat/chat.css, overridden to these warm values at the end of that file with !important so every theme (Light, Dark, System) is warm. When chat.css changes, bump its cache-buster (chat.css?v=N) in the pages that link it.

• The ARC pages (arc.html, attempts.html) set these colours directly in their own inline styles.

• The one exception is the ARC game grid itself: the small COLORS map that renders ARC-AGI-3 cell values (0..15) keeps the standard ARC colours, because those are game data, not page chrome.

Rules for new pages:

• Use the palette above. Backgrounds dark red; text light yellow or gold; accents crimson/yellow/limoncello. No cool colours in the chrome.

• The pressed-inverted button rule below still applies (it inverts whatever warm colours a button has).


BUTTON PRESS RULE

Every button on every page must show an inverted colour scheme while it is being pressed, and must take its action when the mouse button is released.

The exact behaviour is:

• While the mouse button is held down on a button (or a select control), the button's colours invert.

• When the mouse button is released over that button, the colours first revert to normal and THEN the button's action fires. This ordering is guaranteed by the browser event sequence mousedown then mouseup then click: the invert is removed on mouseup, and the action runs on the click event that follows, so the button is already back to its normal colours by the time the action fires.

• If the mouse is dragged off the button while still held down, the button's colours revert and no action fires (again, the normal browser behaviour for a cancelled click).

How it is implemented:

• A single shared script provides this for all buttons on a page: assets/common/press.js

• It is self-contained (it injects its own style), theme-agnostic (it inverts whatever colours a button already has, using a CSS filter), and needs no per-page styling.

• Every served HTML page includes it once, just before the closing body tag:

  <script src="/assets/common/press.js"></script>

Rules for new pages:

• Any new HTML page the server serves MUST include that one line.

• Do NOT re-implement pressed-button styling per page. If the shared behaviour needs to change, change assets/common/press.js in one place.

Pages currently covered:

• assets/arc/arc.html - the ARC-AGI-3 Chat page.

• assets/arc/attempts.html - the ARC-AGI-3 Solo Attempts Record page.

• assets/chat/index.html - the public chat page.

• assets/chat/mentor.html - the Mentor Panel (sign-in, teach, review, and the Mentor Token tool).

• assets/chat/terms.html - the Terms of Use page.
