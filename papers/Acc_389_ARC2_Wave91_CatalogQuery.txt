TASK DESCRIPTION

Task d8e07eb2 presents five training pairs and one test case. All
twelve grids are 30x22 with dimensions preserved. Every input
carries the same fixed body: a four-by-four catalog of sixteen
three-by-three colored shapes, laid out at a five-cell pitch
between two solid separator rows of color 6 (rows 5 and 27). Above
the upper separator sits the header band, which shows up to four
query shapes in slots at the same column pitch; below the lower
separator sits a two-row footer band of blank background. Each
query shape is an exact cell-for-cell copy of one catalog block,
colors included. The output highlights every matched catalog block
by turning the background 8 cells of its five-by-five frame box -
the block plus a one-cell border - to color 3, keeping all shape
cells. When all matched blocks share one catalog row or one catalog
column, the header band is highlighted the same way and the footer
rows fill with color 3; otherwise the header stays untouched and
the footer rows fill with color 2.

RULE: catalog_query

The glass-box rule is a four-stage procedure whose parameters are
all read off the input grid at solve time:

1. CATALOG EXTRACTION (cq_block_/4, cq_seg_/4)
   The sixteen catalog blocks are cut out of the body at the fixed
   five-cell pitch: block (i, j) occupies rows 8 + 5i to 10 + 5i
   and columns 2 + 5j to 4 + 5j for i, j in 0 to 3.

2. QUERY EXTRACTION (cq_block_/4, cq_blank_/1)
   The header slots are cut out of rows 1 to 3 at the same column
   pitch; a slot is a query when it holds at least one non-8 cell.
   The training pairs show three-query and four-query headers.

3. EXACT MATCHING
   Every query shape is matched against the catalog cell for cell,
   colors included. Each query matches exactly one block. The color
   part of the match is essential: the catalog contains same-shape
   different-color decoys, such as the ring-of-eight shape that
   appears once in color 1 and once in color 2.

4. HIGHLIGHT RENDERING (cq_paint_/6)
   Every matched block's five-by-five frame box - rows 7 + 5i to
   11 + 5i, columns 1 + 5j to 5 + 5j - is highlighted by promoting
   its background 8 cells to color 3. If all matches share one
   catalog row index or one catalog column index, the header band
   (rows 0 to 4) is highlighted the same way and the footer rows
   28 to 29 fill with color 3; otherwise the footer rows fill with
   color 2 and the header is untouched. Adjacent boxes merge into
   one continuous band with no special banding logic, because only
   background cells are promoted.

KEY INSIGHT

The alignment verdict is the discriminating observation of the
wave. Two training pairs highlight the header and paint the footer
with color 3; three leave the header alone and paint the footer
with color 2. The split is exactly whether the matched blocks all
sit in one catalog row or one catalog column - a compact global
summary of the query answer, not a property of any single match.
A second exploitable invariant is the fixed body: every input
carries the same sixteen-block scenery, so the scenery is a lookup
table and all variation lives in the small header query region.
The test grid exercises the aligned case with four queries that
all resolve to the last catalog column.

INDUCTION AND VERIFICATION

The rule has no learned parameters. The catalog, the queries, the
matches, and the alignment verdict are all read off the input grid
at answer time. Induction is pure verification: a cheap pre-filter
(exactly 30 rows and 22 columns with height preserved, and solid
color-6 separator rows at rows 5 and 27) followed by transformation
of every training pair. The Python prototype passed all five
training pairs and the test case on the first run, and the
integrated Prolog rule passed the single-task test and the full
regression of all 87 locally verified tasks on the first compile.
